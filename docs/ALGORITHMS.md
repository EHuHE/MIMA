# 算法与搜索策略：从零开始

## 1. 我们究竟在优化什么

输入整数 `X` 的第 `i` 位是 `x_i`，即 `X = sum(x_i * 2^i)`；输出采用同一位序。
固定真值表给出了 64 个输入的唯一正确答案。候选不是另一个 S 盒，而是同一张真值表的
不同逻辑门实现。

候选可以表示为有向无环图：主输入和逻辑门输出是“网络”，逻辑门是节点，连线表示依赖。
无环保证它是纯组合电路。每个网络只能有一个驱动者，否则硬件含义不唯一。

## 2. 为什么必须分开看两个延时

### 理论延时 `D_theory`

给每种门一个固定延时。某个门的到达时间等于“所有输入到达时间的最大值 + 本门延时”。
按拓扑序计算所有门后，六个输出到达时间的最大值就是 `D_theory`。这本质上是 DAG 上的
加权最长路径，时间复杂度是 `O(V + E)`。

优点是快速、确定、适合搜索内层循环；缺点是没有刻画真实扇出、不同引脚、综合重写和映射。

### 实际延时 `D_sta`

结构化 VHDL 经过统一综合和映射后，由静态时序分析读取标准单元库，检查六个输出的最坏
传播路径。两个理论图即使 `D_theory` 相同，也可能因为扇出和引脚选择得到不同 `D_sta`。

所以搜索不能用一个指标覆盖另一个指标。本项目分别维护理论榜、STA 榜和
`(D_theory, D_sta, area)` Pareto 前沿。

## 3. 为什么选择结构化门级表示

直接从真值表综合很方便，但综合器需要自行猜测逻辑分解，结果容易受启发式和版本影响。
结构化网表明确规定每一个门和连接，能稳定表达已经找到的低延时结构，也更容易建立理论图
与实际 VHDL 的一一对应。本仓库会把 `theory.json` 确定性渲染为 `SB.vhd`，并逐字节核对。

## 4. 候选如何产生

项目采用分层混合搜索，而不是把所有可能电路一次枚举完：

1. **真值签名。** 对每个内部网络计算一个 64 位签名，第 `X` 位就是输入 `X` 时该网络的值。
2. **等价网络 CSE。** 签名相同的两个网络实现相同布尔函数，可以尝试保留一个、替换另一个，
   从而减少门或改变扇出。`mima-search-cse` 实现了可复现的单步版本。
3. **代数局部替换。** 用逻辑等价的合法门组合替换局部锥。例如当前 STA 代表用一个
   `OAI21` 替换原 `NAND2` 连接，并删除成为死逻辑的门。
4. **驱动与引脚搜索。** 同一个逻辑值可能有多个物理来源；切换等价驱动或交换等价引脚不会
   改变真值表，却可能改善关键网络的负载和映射。
5. **两级筛选。** 所有变体先做 64 项功能、结构和 `D_theory` 检查；只有有希望且互不重复的
   结构才进入昂贵 STA。未运行 STA 的结果明确标为 `NOT_RUN`。
6. **晋级复验。** 改进候选必须执行两次 fresh 运行并独立审计，随后才更新榜单。

## 5. 搜索算法怎样选择

| 方法 | 适用场景 | 主要问题 | 本项目用法 |
|---|---|---|---|
| 全枚举 | 很小且边界明确的局部空间 | 空间很快爆炸 | 用于单门、引脚和小坐标域 |
| 局部搜索 | 已有强父候选 | 可能停在局部最优 | 用于驱动、负载和等价门替换 |
| Beam search | 每层有大量候选 | 宽度和评分会引入偏差 | 保留若干结构差异大的前沿点 |
| SAT/SMT | 需要证明局部不可达或寻找精确结构 | 编码和超时成本高 | 只对边界明确的子问题使用 |
| STA 引导 | 最接近最终评价 | 单次成本高且有工具噪声 | 只用于通过静态筛选的少量候选 |

当前公开代码优先提供容易审计的确定性 CSE 搜索。它按理论延时、门数和稳定名称排序，绝不
根据理论指标猜测 `D_sta`。
